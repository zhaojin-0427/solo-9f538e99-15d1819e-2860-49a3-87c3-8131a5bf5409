# 口述史馆 · 检索字幕

为口述史馆的单期访谈原片维护「检索字幕」：上传原片 WebVTT 与剪辑 CSV，按剪辑表拼接片段并逐次校订被剪口截断的字幕，发布后按版号下载完整 WebVTT。

## 启动

```bash
docker compose up --build
```

打开 <http://localhost:8000>。数据库保存在名为 `oral-history-data` 的卷里，重启容器后已发布版本仍可原样下载。

本地开发：

```bash
python3 -m pip install -r requirements.txt
ORAL_HISTORY_DB=./data/oral_history.db flask --app app.wsgi run --debug
```

## 使用流程

1. **上传单期原片**：一个 WebVTT + 一个剪辑 CSV。
   - CSV 列：`片段号,原片起毫秒,原片止毫秒`（也接受 `fragment_no,start_ms,end_ms`；无表头时按此顺序读取）。
   - 行序即拼接顺序；片段号在表内唯一；**同一原片时段允许被多个片段号重复取用**。
2. **分页校订**：草稿按剪辑顺序分页，**每页最多 20 个片段**，表单只提交本页出现，上千处剪口也不会超过 32 MiB 请求上限。
   - 可在「全部片段」与「仅含待校订剪口」两个范围间切换；后者只列出仍含待处理剪口的片段。
   - 整条落在片段内的字幕标记为「整条保留」，沿用正文，无需录入。
   - 被剪口截断的字幕标记为「剪口截断」，须**逐次**录入保留文字或标为删除；同一片段重复出现时各算一次。
   - 已保存的校订可随时翻回该页查看、修改。每页页头都显示**全稿待校订总数**。
   - 待校订列表因其他页保存而缩短时，分页按当前片段序号窗口取数，继续翻页不会漏掉后面的待校订片段；保存只写入表单本页显示的出现。
3. **发布**：以数据库里整份草稿已保存的校订为准，全稿还有一处待校订就不产生新版本；发布成功后按剪辑顺序生成完整 WebVTT 并分配版号。
4. **更换剪辑表**：重新上传即建立新草稿，每一次出现都会重新计算节选时码；旧草稿页再提交会返回 409 并提示刷新。

## 规则要点

- **只计算一次**：建稿时片段与每一次字幕出现即持久化到 SQLite（`fragment` / `occurrence` 表）。除**旧草稿首次载入的一次性回填**外，打开或保存任何一页都只走索引查询，不解析 VTT、不重算整份剪辑表。
- **旧卷兼容**：旧版本 SQLite 卷（没有 `fragment` / `occurrence` 表）里的草稿与校订可继续使用，首次打开时自动回填；回填完成前直接提交会提示先刷新页面。
- **校订沿用**：仅当「片段号 + 原字幕正文 + 保留的原片范围」三者完全一致时，才沿用上一版校订；剪辑表或原片范围一变即需重新录入。
- **旧页面拒绝**：上传新剪辑表或发布成功后，先前打开的草稿页提交校订/发布会被拒绝（HTTP 409），提示刷新后重新录入。
- **请求上限**：表单提交超过 32 MiB 时整次请求被拒绝且不写入任何内容，页面提示回到分页校订。
- **发布原子性**：有未处理剪口、版本冲突或写入失败时不会产生新版本；已发布版本存在 SQLite 中，重启后按版号原样下载。

## 项目结构

```
app/core.py         领域逻辑：时码、WebVTT、剪辑 CSV、出现计算、持久化、校订继承、SQLite
app/app.py          Flask 路由（分页校订、保存、发布、413 处理）
app/templates/      页面模板
app/static/style.css
tests/              单元测试与网页流程测试
examples/           示例 WebVTT 与剪辑 CSV
```
